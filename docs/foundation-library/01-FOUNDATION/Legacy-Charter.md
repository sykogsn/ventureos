# Legacy Charter

**Purpose.** Bind the Foundation Library to outlive sprints, tools, and individual authors.

**Authority.** Charter for this library. It does not freeze product roadmap; it freezes how knowledge is kept.

**Audience.** Foundation owners, reviewers, and anyone tempted to put law in a chat transcript.

**Dependencies.** [VentureOS Creed](./VentureOS-Creed.md) · [Foundation Governance](./Foundation-Governance.md)

**Related Documents.** [Master Engineering Prompt](../../engineering/MASTER_ENGINEERING_PROMPT.md) · [Engineering Index](../../engineering/README.md) · [Start Here](../00-START-HERE.md) · [Source Map](../99-APPENDIX/Source-Map.md) · [Sprint Standard](../04-ENGINEERING/Sprint-Standard.md)

**Last Updated.** 2026-08-20

---

VentureOS is built to be operated for decades of company life, not for a demo week.

Code moves. Chat does not. The Foundation Library is the memory of the OS.

## What this library must remain

- The single reading system for philosophy, architecture, design, engineering, governance, and products.
- Connected. Every document names related documents. Isolated pages are a defect.
- Honest about lock versus living registers. A creed is approved. A debt register is living.
- Compatible with the documents that already sit beside the code. This library consolidates understanding. It does not fork a second architecture.

## What this library must not become

- A dump of sprint tickets.
- A second IDS, Runtime, or Definition Registry.
- Marketing prose that cannot be implemented.
- A place to hide an architecture change that did not survive review.

## Preservation

Existing Foundation specifications under `docs/foundation/` and code-adjacent READMEs remain. When a library document and a specification disagree on a technical fact, the specification and the code win, and the library must be corrected.

Do not delete a specification because it has been explained here. Supersession is explicit, dated, and recorded in the [Release Register](../05-GOVERNANCE/Release-Register.md).

## Duty

If you change a locked boundary, you amend Foundation.

If you learn something the library does not say, you add it to the correct document in the same sprint, or you record the gap in the [Assumption Register](../05-GOVERNANCE/Assumption-Register.md).
